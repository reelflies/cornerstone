# ReelFlies customisations

This repo is Cornerstone (`upstream`, bigcommerce/cornerstone) plus ReelFlies code. The rules come from [ADR 0001](docs/adr/0001-scoped-theme-code.md). This file is the register of every upstream file ReelFlies has changed. Update it in the same PR as the change.

## The Streamside Stone rebuild (branch `redesign/streamside-stone`)

The owner chose a clean fork for the redesign (2026-11-06). On this branch the bundled theme (`assets`, `templates`, `lang`, `meta`, `config.json`, `schema.json`, `schemaTranslations.json`) went back to untouched Cornerstone 6.22.0, and the new look is built on it from DESIGN.md, page by page. The rules of ADR 0001 still hold.

- **[Upstream files changed](#upstream-files-changed)** lists only what this branch has hooked so far.
- **[On master, to carry back](#on-master-to-carry-back)** is master's register as it stood at the fork (62e7afe5). Each feature comes back with the page it belongs to, redrawn in the new look wherever it draws anything, and its rows move up when it lands. Decisions the redesign replaced (the sage buy colour, Onest, the Hook Gauge tiles, bands and footer) don't come back.
- **The slots** in the next sections (`page-modules.js`, `global.js`, `js-settings.html`, the `rf_*` settings groups) return with the first module that needs them.
- **`npm run test:scripts`** fails on this branch until then: 576 of 3,103 tests fail and 66 are cancelled, asserting features or values from master's skin (2026-11-07, after step 3; 612 failed after step 2; 515 of 2,967 after step 1). Each module's tests return or are rewritten with it. Don't release from this branch before they pass.

### Step 2: the shell and the home page

Every page now has the ReelFlies strip, header (Flies and Species mega menus, the phone drawer), footer and order line; the home page is `prototype/home-v2` in Stencil. Code: `templates/components/reelflies/`, `assets/scss/reelflies/` (`_shell`, `_footer`, `_fly`, `_order-line`, `_home`) and `assets/js/theme/reelflies/`.

- **Where the data comes from.** Menus, ways in, plates, the moss band and the footer: the `categories` data, by the ids in the Menu settings (`rf_menu_type_ids`, `rf_menu_species_root_id`, `rf_species_salt_ids`, `rf_menu_link_ids`, `rf_menu_also_ids`), so the channel's Menu Display Depth must be 3. Best sellers: `products.top_sellers`, with their sizes and stock from the home page's GraphQL front matter. The hatch chart's flies, the Signature fly and the Selections: product ids in Theme Styles (Hatch chart, Home page), read by that front matter, so the owner swaps them without a push. A way in or a species re-lays its flies through the Storefront GraphQL API (search, best selling), in the browser.
- **The hatch chart** is theme data (`components/reelflies/hatches.html`: names, Latin names, hook ranges, months), with each row's flies and "More" category as settings. DESIGN.md had planned a Page Builder widget; that needs a widget template written to the store, so it waits for the owner.
- **The box** is the Storefront Cart API (`box.js`): changes show at once and run one call at a time. QA must never add to a live channel's cart; `scripts/qa`'s network guard refuses those writes, and the home checks in this step mocked the Cart API.
- **Counts** beside categories are BigCommerce's own (`rf_counts`), and the stone's and the moss's "All n" links repeat the same figure, so a category never shows two. A parent's count adds up its subcategories, so it overstates: Nymphs & Sub Surface Flies reports 1,446 on tree 1, and a search of the category finds 756 unique products. The Storefront API's search (`collectionInfo.totalItems`) gives the unique figure; switching every count to it is open.
- **Variation values.** ReelFlies CA (1895766): none yet; its menu ids wait for tree 4 (wave R1), so the prelaunch storefront shows the stone, the hatch chart and the shop until then. ReelFlies US: tree 2's Fly Types, no shipping threshold, reelflies.com's name and link to reelflies.ca. ReelFlies CA channel 1: tree 1's Fly Types, plain links, "Also" row, "/ fly" roots, Signature and Selections categories and the hatch rows' "More" categories, and `rf_quick_add` false (the owner's channel-1 value from master, so "+ Add" reads "Choose a size" there).
- **Retired with the stock header and home:** the shipping-strip widget in `header_bottom--global` and the home page's Page Builder widgets (1895766 and channel 1) no longer render. They stay stored in BigCommerce.

### Changing a pre-declared value

The release guard's rule 1 covers every `rf_*` key except the two menu ids, values as well as switches ([releasing](docs/releasing.md#the-release-guard)). So once ticket 25's push has put the block live on 1895766, a `config.json` change to any pre-declared key stops every release of `master` with "No flag overrides this", until the live value matches. That includes the value keys `rf_menu_exclude_ids`, `rf_price_unit_exclude`, `rf_ship_*` and `rf_store_same_as`, and a key you add yourself, from its own first push on.

- **Until the release lane gives values step 1's three-way rule,** as the menu ids have (asked for on PR #29; a todo test in `scaffold.test.mjs` holds the behaviour it should have):
  1. The value is set in Theme Styles on 1895766 first, and logged under "Switch toggles" in `RELEASES.md`. Agents have no route for that edit, so ask the orchestrator to put it in Shaun's batch.
  2. Then `config.json` changes to match. Don't merge that change before the live value matches: merged first, it stops the next release of `master` for every ticket. Until then, mark the criterion that needs the value waiting, with that trigger.
- **The switches** stay under rule 1 for good: toggle them in Theme Styles, log the toggle, then change `config.json` ([switch toggles](docs/releasing.md#switch-toggles)).

## Never

- Edit the folders `config.json` lists as `read_only_files`:
  - `assets/scss/settings/{citadel,foundation,normalize,vendor}`
  - `assets/scss/components/{citadel,foundation,vendor}`
  - `assets/scss/vendor`
- Edit or regenerate `assets/img/icon-sprite.svg`.
- Auto-format an upstream file (prettier, `eslint --fix`, `stylelint --fix`). Only the hook lines may change.
- Delete an upstream schema entry. Hide it instead, if a setting must not be used.
- Put a token or key in a theme setting. `templates/pages/account/add-payment-method.html:31` exposes all of them to the page's JavaScript.
- Take a category out of Google any way but the noindex template (below). Script Manager canonicals are forbidden (refactor 11).

### Taking a category out of Google (ticket 32; R13, SEO-10)

The only approved way is the custom category template `templates/pages/custom/category/rf-noindex.html`: the same page as the stock category template, plus one robots meta, "noindex, follow", so Google drops the page and still follows its links.

- **Switching a category to it** is a template association in the control panel (or, on 1895766, a custom template association through the store-write helper), with no theme push. It counts only once the active theme contains the template.
- **Before the first category moves onto it,** the category also comes out of the menus (ticket 28's menu reads `rf_menu_exclude_ids` for the top level only; a child in a pane needs the same) and out of hreflang (ticket 19). Ticket 32's comment of 2026-10-09 records this as the open step.
- **Locally,** `scripts/qa/custom-layouts.json` maps it to channel 1's `category@noindex` pin, and the `category-robots` raw-HTML assertion holds its one robots meta.
- **Keep it in step** with `pages/category.html`: `render/partials/category.test.mjs` fails when the two pages differ but for the meta.

### The Species hub (ticket 34; spec module 10; R8, SEO-2)

The Species root, "Flies by Species" at `/species/`, renders with the custom category template `templates/pages/custom/category/species-hub.html`: the H1 "Fly Fishing Flies by Species", the root's intro, one tile per Species page (`components/reelflies/category-tile.html`) with its Fly Type links, then the grid with the numbered pager. It is a new file, not a hook: no stock line changes. Its card include passes ticket 43's `rf_quick_add_card=true`, so its grid's cards get quick add's "+ Add" (`quick-add-gate.html`) without `rf_listing`, which would make its first three card photos eager (34's criterion 5).

- **Switching the root to it** is a template association, as for the noindex template: on 1895766 through the store-write helper (snapshot, diff, log row), and only once a release has put the template in the active theme. Reverting it needs no push.
- **The Fly Type links need Menu Display Depth 3 or more** on the channel (the root, the Species pages and their Species × Fly Type pages in the `categories` data). Refactor 07 owns that setting; with less, the tiles show no links.
- **Locally,** `scripts/qa/custom-layouts.json` maps it to channel 1's `species-hub` pin (Saltwater, Warmwater & Salmon, a stand-in until wave R2 pins `/species/` on 1895766, once refactor 14 has placed the products), and the `species-hub` raw-HTML assertion holds the page. The shipping strip lists it in its `template_files` ([widgets](docs/widgets.md)).

## Upgrading to a new Cornerstone release

1. `git fetch upstream --tags`, then fast-forward `vendor/cornerstone` to the new tag and push it.
2. Branch `upgrade/<tag>` from `master` and merge `vendor/cornerstone` into it.
3. Resolve conflicts. They should only be at the files listed above.
   - For `package-lock.json`, take upstream's version and re-run `npm install --save-dev --save-exact @bigcommerce/stencil-cli@9.1.0`, then `npm install --save-dev --save-exact @playwright/test@1.59.1 @axe-core/playwright@4.10.2`.
   - If upstream has moved `.nvmrc`, check that the pinned stencil-cli still supports that Node version.
4. Open a PR. CI runs the checks.
5. Run `npm run qa:screens`, which starts `npx stencil start -c 1895766` (ReelFlies_CA) itself, and `QA_CHANNEL=1 npm run qa:screens` for the product and category pages until ReelFlies_CA has them. A failed diff shows what the merge changed: fix it, or update the baseline only for a change you meant ([scripts/qa/README.md](scripts/qa/README.md)).
6. Merge to `master`.
